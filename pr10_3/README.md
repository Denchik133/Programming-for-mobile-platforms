# Практична робота №10 (Частина 3) — Міграції, оптимізація та best practices

## Варіант 5. Шар валідації даних

### 1. Опис проєкту

Flutter-застосунок для створення контактів із перевіркою даних перед збереженням у SQLite. Він демонструє очищення введених значень, валідацію полів, обробку помилок і роботу з локальною базою.

Основні можливості:
- додавання контактів з ім’ям, електронною поштою та телефоном;
- нормалізація введених даних до перевірки;
- окремі повідомлення про помилки біля кожного поля;
- збереження валідних контактів у SQLite;
- перегляд і видалення збережених контактів;
- обробка повторної електронної адреси та помилок сховища.

Варіант 5 обрано як найпростіший серед шести: він зосереджений на перевірці даних перед записом і не вимагає міграцій, бенчмарків, кількох реалізацій репозиторію, пулу з’єднань чи SQL-тригерів.

### 2. Технології

- Flutter і Dart;
- SQLite через пакет `sqflite`;
- `ContactSanitizer` для очищення вводу;
- `ContactValidator` для перевірки полів;
- `ContactService` для послідовності очищення, валідації та запису;
- Repository Pattern для відокремлення збереження даних від UI;
- `flutter_test` для модульних тестів із тестовим репозиторієм.

### 5. Очищення та валідація даних

#### Очищення

У `lib/validation/contact_sanitizer.dart` клас `ContactSanitizer` виконує нормалізацію перед перевіркою:
- для імені замінює керівні символи пробілами, згортає послідовності пробілів та обрізає краї;
- для email обрізає пробіли та переводить адресу до нижнього регістру;
- для телефону видаляє пробіли й роздільники `(`, `)`, `-`, `.`.

Інші потенційно некоректні символи санітизатор не прибирає мовчки — їх має відхилити валідатор.

#### Перевірки полів

У `lib/validation/contact_validator.dart` клас `ContactValidator` повертає мапу помилок за назвами полів:
- **Ім’я:** обов’язкове, від 2 до 60 символів, має містити літери; символи `<` і `>` відхиляються.
- **Email:** перевіряється формат і максимальна довжина 254 символи.
- **Телефон:** 7–15 цифр, за потреби знак `+` на початку.

`ContactsScreen` показує помилки безпосередньо біля полів форми.

### 6. Перевірка перед записом

Метод `ContactService.createContact()` у `lib/services/contact_service.dart` виконує операції в такому порядку:

```text
Ввід → ContactSanitizer → ContactValidator → ContactRepository → SQLite
```

Якщо є помилки валідації, сервіс викидає `ContactValidationException` і не викликає репозиторій. Для валідного контакту він передає нормалізовані значення до `ContactRepository`. UI не містить правил роботи з SQL.

`ContactRepository` задає контракт сховища, а `SqliteContactRepository` реалізує його через `sqflite`. Введені значення передаються параметрами; SQL-рядки не формуються конкатенацією користувацького вводу.

### 7. SQLite та обробка помилок

Таблиця `contacts` зберігає ім’я, email, телефон і час створення. Email має обмеження `UNIQUE` без урахування регістру, тому повторну адресу база відхиляє.

Помилки читання, запису та видалення репозиторій-сервіс обгортає в `ContactStorageException`. Інтерфейс показує повідомлення про проблему зі сховищем; якщо базу не вдалося відкрити під час запуску, відображається окремий екран помилки.

### 8. Тестування

Тести в каталозі `test/` перевіряють:
- нормалізацію імені, email і телефону;
- відхилення некоректних значень;
- те, що при помилці валідації репозиторій не викликається;
- збереження лише очищених значень;
- перетворення помилки сховища на `ContactStorageException`.

Результати перевірки:
- `flutter test` — 7 тестів пройшли;
- `flutter analyze` — помилок та зауважень не знайдено.
