# Практична робота 10 (частина 2): система обробки замовлень

**Варіант:** 1 — SQLite Transactions  
**Дисципліна:** Програмування для мобільних платформ  
**Тема:** транзакції, пакетні операції та цілісність локальних даних

## Опис проєкту

Застосунок дає змогу вести локальний каталог товарів, оформлювати замовлення та переглядати їхній стан. Він зберігає товари, замовлення й позиції замовлень у SQLite. Транзакції об’єднують створення замовлення, додавання його позицій і списання товарів зі складу в одну операцію: якщо перевірка або запис завершується помилкою, зміни транзакції відкочуються.

## Мета роботи

Мета — опрацювати використання SQLite у Flutter-застосунку: зв’язки між таблицями, зовнішні ключі, індекси, транзакції та пакетне виконання запитів. Також реалізовано вибірки з `JOIN` і агрегування даних для звітів.

## Використані технології

- **Dart** — мова програмування.
- **Flutter** — UI застосунку; використано Material-компоненти.
- **SQLite** через `sqflite` — локальне збереження даних.
- **`sqflite_common_ffi`** — SQLite FFI для desktop-запуску та in-memory бази у тестах.
- **`path`** — формування шляху до файлу бази даних.
- **`intl`** — форматування сум і дат в інтерфейсі.
- **`flutter_test`** — наявний набір автоматизованих тестів.
- **Flutter SDK і Pub** — запуск застосунку та керування залежностями.

## Функціональні можливості

- Перегляд замовлень і фільтрація за статусами: в обробці, виконано, скасовано.
- Перегляд складу, додавання товару та поповнення його залишку.
- Створення замовлення з вибором кількості товарів. Ціни й підсумкова сума беруться з бази даних.
- Скасування замовлення зі зміною статусу та поверненням товарів на склад; завершення замовлення.
- Демонстраційна кнопка **«Тест Rollback»**: формує замовлення з кількістю, більшою за доступний залишок, щоб показати повідомлення про помилку та відкат транзакції.
- Режим вибору кількох замовлень і пакетна зміна їхніх статусів.
- Видалення виконаних замовлень, старших за обрану кількість днів. Пов’язані позиції видаляються завдяки зовнішньому ключу `ON DELETE CASCADE`.
- Перегляд виторгу від виконаних замовлень, кількості замовлень за статусами та рейтингу товарів за кількістю проданих одиниць у виконаних замовленнях.
- Генерація демонстраційних замовлень і скидання локальних даних до початкового каталогу товарів.

## Архітектура та реалізація

Застосунок розділено на екрани, моделі, репозиторії, сервіс бізнес-логіки та клас роботи з базою даних. Основний потік такий: екран викликає сервіс або репозиторій, вони читають чи змінюють SQLite, а результат відображається в інтерфейсі.

База даних `orders_system.db` має три таблиці:

- `products` — назва товару, ціна та залишок;
- `orders` — ID клієнта, загальна сума, статус і дата створення;
- `order_items` — ID замовлення й товару, кількість та ціна на момент оформлення.

У `order_items` зовнішній ключ на `orders` має `ON DELETE CASCADE`, а зовнішній ключ на `products` забезпечує посилальну цілісність. Під час конфігурації з’єднання вмикається `PRAGMA foreign_keys = ON`. Індекси створюються для `orders.userId`, `order_items.orderId` і `order_items.productId`. Під час першого створення БД початкові товари додаються пакетною операцією.

`OrderService.createOrder` перевіряє, що запит містить товари, знаходить кожен товар і перевіряє його залишок. Потім сервіс бере актуальні ціни з БД, додає заголовок замовлення та його позиції й зменшує залишки в межах `db.transaction`. Якщо виникає помилка, вона передається екрану створення замовлення, який показує повідомлення. Скасування також виконується транзакційно: кількість повертається на склад, а статус змінюється на `cancelled`. Завершення змінює статус лише замовлення зі статусом `pending`.

`OrderRepository` виконує запити списку й деталей замовлення, зокрема `LEFT JOIN` для підрахунку позицій і `INNER JOIN` для назв товарів. `ProductRepository` містить операції читання та зміни каталогу. Пакетні вставки використовуються для початкових товарів, а `OrderService.updateOrdersStatus` застосовує `db.batch()` для оновлення кількох статусів. `deleteOldOrders` виконує один запит видалення за датою та статусом; це масове видалення, а не окремий виклик `db.batch()`.

Екран аналітики використовує SQL-агрегації: виторг рахується лише за виконаними замовленнями, кількість — окремо за кожним статусом, а популярність товарів — за сумою кількостей у позиціях виконаних замовлень. Для desktop у `main.dart` ініціалізується FFI-рушій SQLite. Дані зберігаються у локальному файлі бази за шляхом, який надає `sqflite` для платформи.

```text
pr10_2/

│   ├── screens/                           # Екрани замовлень, створення, складу й аналітики
│   ├── services/order_service.dart        # Транзакції, пакетні оновлення та звіти
│   └── main.dart                          # Ініціалізація та навігація
├── test/orders_transaction_test.dart     # Тести транзакцій, каскаду, пакетних запитів і звітів
├── analysis_options.yaml                 # Налаштування аналізатора Dart
├── pubspec.yaml                          # Залежності та параметри Flutter-проєкту
├── pubspec.lock                          # Зафіксовані версії залежностей
└── run.sh                                # Локальний допоміжний скрипт запуску macOS
```

## Встановлення та запуск

Потрібні встановлені Flutter SDK і доступний пристрій або емулятор. Перевірити доступні цілі запуску можна командою `flutter devices`.

```bash
cd pr10_2
flutter pub get
flutter devices
```

Запуск desktop-збірки на macOS:

```bash
flutter run -d macos
```

Запуск на підключеному пристрої або запущеному емуляторі Android/iOS (підставте ID зі списку `flutter devices`):

```bash
flutter run -d <device_id>
```

У кореневій папці також є `run.sh`, але він містить абсолютний шлях до Flutter SDK конкретної машини. Для іншого середовища використовуйте наведені вище команди Flutter.

## Тести

У проєкті є файл `test/orders_transaction_test.dart` з тестами створення замовлення, відкату при нестачі товару, скасування, каскадного видалення, пакетної зміни статусів і звітів. Запустити набір можна командою:
